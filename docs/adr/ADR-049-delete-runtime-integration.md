# ADR-049 — Delete Runtime Integration

## Status

Accepted — Milestone 6.28.

## Decision

The Java Spring Clean multi-module Golden Path generates physical delete through
Core and the JPA persistence adapter only. Each entity receives
`Delete<Entity>Command`, `Delete<Entity>UseCase`, and
`Delete<Entity>UseCaseInteractor`; the Core gateway adds
`void deleteById(identifier)`. The interactor validates the command and
delegates the identifier without loading or returning a domain entity.

The JPA provider requires a non-null identifier, checks `existsById`, maps
absence to `NotFoundException` with the existing `<domain>.not-found` key, and
calls repository `deleteById` only when the record exists. Repository, entity,
schema, and POM contracts remain unchanged. Configuration registers the delete
use case explicitly.

The generated persistence test proves existing deletion, missing-ID rejection,
and repeated-deletion rejection with H2. The generated Core test proves null
command and identifier validation plus one exact void delegation.

## Scope boundary

No DELETE controller mapping, REST DTO, OpenAPI operation, HTTP test, request
model, or single-module/POM artifact is generated by this milestone. HTTP and
OpenAPI delete exposure is a later capability.

## Consequences

The full multi-module profile increases from 119 to 124 artifacts. The Core
selection increases from 46 to 50, while transitive REST and infrastructure
selection counts increase to 69 and 68 respectively. The configuration
selection becomes 124. Existing REST and OpenAPI output remains unchanged.
